Aquí tienes el **Plan de Implementación Técnica para el Backend** de **Finance AI**, estructurado para unificar los requerimientos del documento ERS con la arquitectura híbrida de clasificación de 4 niveles.

Este plan abarca desde la preparación de la base de datos hasta el motor de clasificación por coincidencias, la integración con el modelo de Ciencia de Datos y el ciclo de retroalimentación de los usuarios (*crowdsourcing*).

---

## 🏗️ Resumen de la Arquitectura de Clasificación (4 Niveles)

El backend procesará cada transacción a través de una cadena jerárquica de 4 niveles:

1. **Nivel 1 (Mapeo BD por Feedback):** Coincidencia exacta con patrones normalizados previamente validados por usuarios (`transaction_category_mappings`).


2. **Nivel 2 (Reglas por Palabras Clave):** Coincidencia mediante un diccionario de reglas estáticas (`CategoryRule`).


3. **Nivel 3 (Modelo ML de Ciencia de Datos):** Inferencia supervisada entrenada en Scikit-Learn que asigna la categoría y calcula la probabilidad.


4. **Nivel 4 (Fallback):** Asignación por defecto a `OTROS_EGRESOS` o `OTROS_INGRESOS`.

### Fase 1: Esquema de Base de Datos y Entidades (JPA)

En esta fase se configuran las tablas en Oracle Autonomous Database para soportar el almacenamiento general y la trazabilidad del modelo de datos.

#### 1.1. Tabla de Mapeo Colaborativo (`transaction_category_mappings`)

* Se crea la tabla para almacenar la coincidencia directa de patrones con contador de frecuencia para aprendizaje colaborativo:



```sql
CREATE TABLE transaction_category_mappings (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    description_pattern VARCHAR(255) NOT NULL UNIQUE,
    category VARCHAR(50) NOT NULL,
    frequency INT DEFAULT 1

```[cite: 2]

#### 1.2. Extensión de la Tabla de Transacciones (`transactions`)
* Además de los campos base (`id`, `description`, `amount`, `date`, `user_id`)[cite: 1], se agregan los campos de trazabilidad para el equipo de Datos[cite: 4, 5]:

  * `probabilidad`: Nivel de confianza retornado por el modelo de ML[cite: 4, 5].

### Fase 2: Componente de Normalización de Texto (`TextNormalizerService`)

Ambos equipos acordaron que el texto de las descripciones bancarias debe homogeneizarse antes de ser evaluado en cualquiera de los niveles[cite: 2, 5].

* **Lógica de Limpieza:**
  * Convertir todo el texto a mayúsculas[cite: 2, 5].
  * Eliminar tildes y caracteres especiales[cite: 2, 5].
  * Remover números, fechas, RUTs o identificadores de sucursal variables (ej: transformar `"COMPRA JUMBO PROVIDENCIA 1234"` en `"COMPRA JUMBO"`)[cite: 2, 5].
  * Colapsar espacios en blanco múltiples y aplicar `.trim()`[cite: 2, 5].

### Fase 3: Motor de Clasificación Jerárquico (`CategoryClassifierService`)

Se implementará el servicio principal en Spring Boot[cite: 1] que ejecute la cadena de decisiones[cite: 2, 5]:

```java
@Service
public class CategoryClassifierService {

    private final CategoryMappingRepository mappingRepository;
    private final MlInferenceService mlInferenceService; // Servicio para consumir el modelo ML

    public ClassificationResult classify(String rawDescription) {
        if (rawDescription == null || rawDescription.isBlank()) {
            return new ClassificationResult(Category.OTHER_EXPENSE, 1.0, "FALLBACK"); //[cite: 2, 5]
        }

        // Paso 0: Normalización[cite: 2, 5]
        String normalized = TextNormalizer.normalize(rawDescription);

        // Nivel 1: Coincidencia en BD por feedback/crowdsourcing[cite: 2, 5]
        Optional<CategoryMapping> mapping = mappingRepository.findByDescriptionPattern(normalized);
        if (mapping.isPresent()) {
            return new ClassificationResult(mapping.get().getCategory(), 1.0, "BD_MAPPING"); //[cite: 2, 5]
        }

        // Nivel 2: Reglas por Palabras Clave[cite: 2, 5]
        Category ruleMatch = CategoryRule.match(normalized);
        if (ruleMatch != null) {
            return new ClassificationResult(ruleMatch, 0.9, "KEYWORD_RULE"); //[cite: 2, 5]
        }

        // Nivel 3: Modelo de Machine Learning (Scikit-Learn)[cite: 4, 5]
        if (mlInferenceService.isAvailable()) {
            MlPrediction prediction = mlInferenceService.predict(normalized);
            if (prediction.getConfidence() >= 0.60) { // Umbral de confianza
                return new ClassificationResult(prediction.getCategory(), prediction.getConfidence(), "ML_MODEL"); //[cite: 4, 5]
            }
        }

        // Nivel 4: Fallback por defecto[cite: 2, 5]
        return new ClassificationResult(Category.OTHER_EXPENSE, 0.0, "FALLBACK"); //[cite: 2, 5]
    }
}

```

### Fase 4: Módulo de Feedback del Cliente y Retroalimentación

Para cumplir con el requerimiento de aprendizaje guiado por las correcciones del cliente:

#### 4.1. Endpoint de Corrección

* **Endpoint:** `PUT /api/transactions/{id}/category`.


* **Entrada:** Identificador de la transacción y la nueva categoría seleccionada por el usuario.



#### 4.2. Lógica de Aprendizaje en Tiempo Real (`learnFromFeedback`)

* Al recibir una corrección del usuario:


1. Se actualiza la transacción específica en la BD asignando la `categoria_usuario` para mantener trazabilidad.


2. Se busca o crea el patrón en `transaction_category_mappings`.


3. Se actualiza la categoría asignada al patrón y se incrementa el contador `frequency`.


4. La corrección queda guardada como registro etiquetado para que el equipo de Datos pueda utilizarlo en el ciclo de reentrenamiento del modelo ML.





---

### Fase 5: Procesamiento de Cartolas e Integración Final

#### 5.1. Extracción de Datos en Cartolas (PDFBox)

* Uso de la librería Apache `pdfbox` para parsear cartolas bancarias cargadas por el usuario.


* Por cada fila leída, se extraen la fecha, el monto y la descripción original.



#### 5.2. Pipeline del Endpoint `POST /analisis-financiero`

* Es el endpoint principal expuesto en Spring Boot:


1. Recibe el payload en JSON con los datos del usuario y sus transacciones.


2. Procesa cada transacción mediante `CategoryClassifierService`.


3. Guarda las transacciones asociándolas al `user_id`.


4. Calcula el total de gastos por categoría y determina el perfil financiero (`SAVER`, `BALANCED`, `SPENDER`, `AT_RISK`).


5. Genera recomendaciones personalizadas y las almacena en la tabla `recommendations`.


6. Devuelve la respuesta estructurada en formato JSON.





---

### Fase 6: Infraestructura OCI, Seguridad y Despliegue

* **Seguridad:** Uso de `spring-boot-starter-security` para el hashing de contraseñas de los usuarios en la tabla `users` y `spring-boot-starter-validation` para validar las entradas HTTP.


* **Despliegue en Red (VCN de OCI):**
* La API Spring Boot se despliega en instancias OCI Compute dentro de una subred privada.


* La base de datos Oracle Autonomous DB y el OCI Object Storage (que almacena el artefacto del modelo ML serializado) operan aislados en la subred privada.


* El tráfico entrante se gestiona a través de un Load Balancer público situado en la subred pública.
