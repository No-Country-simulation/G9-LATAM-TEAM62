## 2. Estado real del código (última revisión del repo `G9-LATAM-TEAM62-main`)

**Backend** (Java 25, Spring Boot 4.1.0):
- Arquitectura en capas: `Controller → Service → Repository`, **persistencia en memoria** (`ConcurrentHashMap`), sin JPA ni base de datos conectada todavía — reconocido como "provisional" por el propio equipo.
- Entidades como POJOs (no `@Entity`): `User`, `Transaction`, `Recommendation` + enums `Category` (13 valores, incluye income/saving), `FinancialProfile`, `SavingFrequency`, `TransactionType`.
- Endpoints existentes: `/api/auth/login`, `/api/users` (CRUD + `/profile`), `/api/transactions` (CRUD), `/api/recommendations` (CRUD sin PUT).
- El cálculo del perfil financiero lo hace una "app externa" (el modelo de Datos) que escribe el resultado vía `PUT /api/users/{id}/profile` — el backend no lo calcula.
- Sin OCI todavía (ni Object Storage ni Autonomous DB conectados), sin springdoc-openapi en el `pom.xml` (aunque el README lo menciona como aspiracional), sin JWT/sesión (login solo valida credenciales).

**Frontend** (Vite + React 19 + TypeScript + Tailwind v4): solo existe una landing page estática (`App.tsx`), sin integración con la API todavía.

## 4. Plan de clasificación — resultado unificado

Un integrante de Backend propuso independientemente un sistema de reglas + mapeos con feedback de usuarios (crowdsourcing). Se unificó con la propuesta de Datos (modelo ML) en una **arquitectura híbrida de 4 niveles**:

```
1. Mapeo exacto en BD (categoria_mapeo)      → Backend
2. Reglas de palabras clave (CategoryRule)    → Backend
3. Modelo ML entrenado (Scikit-Learn)         → Datos
4. Fallback OTROS_EGRESOS / OTROS_INGRESOS    → ambos
```

Detalle completo, diagrama Mermaid y tabla de responsables: ver `plan-clasificacion-unificado.md`.

**Puntos clave a no perder:**
- Ambos equipos llegaron independientemente a la misma necesidad de **normalización de texto** (mayúsculas, sin tildes, sin números/códigos variables) antes de clasificar.
- El SQL original del compañero (`BIGINT GENERATED BY DEFAULT AS IDENTITY`) no es válido en Oracle — ya se corrigió en `schema.sql` (ver sección 5).
- El nivel 3 (modelo) se inserta **antes** del fallback que el backend ya tenía, no lo reemplaza — es un cambio incremental.

## 5. Código entregado en esta conversación (carpeta `backend-aporte/`)

Diseñado para integrarse sin romper nada del código existente — son archivos nuevos + 3 archivos modificados de forma incremental.

**Nuevos:**
- `model/PaymentMethod.java` — CASH, DEBIT (tarjeta de crédito **excluida del MVP** a propósito)
- `model/TransactionSource.java` — BANK, MANUAL
- `model/LinkStatus.java` — UNLINKED, AUTOMATIC, USER_CONFIRMED (estado de conciliación cartola↔registro manual)
- `model/CategoryMethod.java` — MAPPING, KEYWORD_RULE, ML_MODEL, FALLBACK, USER_PROVIDED, USER_CORRECTED
- `dto/ManualTransactionRequest.java` — payload del registro manual (userId, amount, category, paymentMethod, description opcional)
- `dto/CategoryCorrectionRequest.java` — payload de la corrección de categoría (solo `category`)

**Modificados (incremental, no reescritura):**
- `model/Transaction.java` — se agregaron `source`, `paymentMethod`, `linkStatus`, `linkedTransactionId`, `categoryMethod`, `categoryConfidence`; `category` dejó de ser `@NotNull` (para que el clasificador la pueda completar después)
- `controller/TransactionController.java` — 2 endpoints nuevos: `POST /api/transactions/manual` y `PUT /api/transactions/{id}/category`
- `service/TransactionService.java` — métodos `createManual()` y `correctCategory()`; comentario en `create()` marcando dónde debe engancharse `CategoryClassifierService` (esa clase la construye Backend, no se implementó acá)

**Importante:** no se pudo compilar con Maven real (el sandbox no tiene salida a Maven Central) — se revisaron imports y referencias a mano contra el repo real. Correr `./mvnw compile` antes de mergear.

### Especificación de los 2 endpoints nuevos

```
POST /api/transactions/manual
{
  "userId": 1,
  "amount": 15.50,
  "category": "FOOD",
  "paymentMethod": "CASH",
  "description": "chocolate"
}
→ 201 Created (source=MANUAL, date=hoy, linkStatus=UNLINKED, categoryMethod=USER_PROVIDED)
```

```
PUT /api/transactions/{id}/category
{ "category": "ENTERTAINMENT" }
→ 200 OK (categoryMethod=USER_CORRECTED, categoryConfidence=null)
```
