# Documentación Técnica — Motor de Clasificación Jerárquico de Transacciones

**Proyecto:** Finance AI — Hackathon G9 LATAM  
**Componente:** Backend (`fintech-api`)  
**Idioma:** Español  

---

## 📌 Visión General

El backend cuenta con un motor de clasificación jerárquico de 4 niveles que analiza la descripción en texto de cada transacción bancaria y le asigna automáticamente la categoría correspondiente (`FOOD`, `TRANSPORT`, `UTILITIES`, etc.).

Además, el sistema cuenta con **aprendizaje continuo en tiempo real (crowdsourcing)**: cuando un usuario corrige manualmente una categoría, el sistema aprende ese patrón en la base de datos para clasificar automáticamente transacciones similares en el futuro.

## 🏗️ Arquitectura de Clasificación (4 Niveles)

```
[Entrada: Descripción en bruto]
         │
         ▼
 ┌───────────────┐
 │TextNormalizer │  Mayúsculas, quita tildes, números, RUTs y caracteres especiales
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │    Nivel 1    │  ¿Coincidencia exacta en transaction_category_mappings?
 │  Crowdsourcing│  ── Sí ──> Confianza 1.0 (BD_MAPPING)
 └───────┬───────┘
         │ No
         ▼
 ┌───────────────┐
 │    Nivel 2    │  ¿Coincidencia de palabra clave en category_keywords?
 │Reglas de BD   │  ── Sí ──> Confianza 0.9 (KEYWORD_RULE)
 └───────┬───────┘
         │ No
         ▼
 ┌───────────────┐
 │    Nivel 3    │  ¿Modelo ML disponible en MlInferenceService y prob >= 0.60?
 │   Modelo ML   │  ── Sí ──> Confianza del modelo (ML_MODEL)
 └───────┬───────┘
         │ No
         ▼
 ┌───────────────┐
 │    Nivel 4    │  Fallback por defecto
 │   Fallback    │  ───────> Categoría OTHER_EXPENSE (Confianza 0.0)
 └───────────────┘
```

## 📂 Clases y Componentes Implementados

### 1. Modelos de Datos (`model`)
- **`CategoryMapping.java`**: Entidad que representa la tabla `transaction_category_mappings`. Guarda el patrón de descripción normalizado, la categoría asociada y el contador de frecuencia de uso.
- **`CategoryKeyword.java`**: Entidad que representa la tabla `category_keywords`. Guarda palabras clave asociadas dinámicamente a cada categoría (ej: "JUMBO" $\rightarrow$ `FOOD`, "UBER" $\rightarrow$ `TRANSPORT`).

### 2. Resultados internos (`service`) y DTOs (`dto`)
- **`ClassificationResult.java`** (`service`): Objeto inmutable que retorna el resultado de la clasificación (`category`, `confidence`, `method`). Vive junto a los servicios y no en `dto` porque nunca cruza HTTP: es el resultado que un servicio le entrega a otro.
- **`MlPrediction.java`** (`service`): Respuesta esperada del modelo ML, también de uso interno.
- **`CategoryCorrectionRequest.java`** (`dto`): DTO para la petición de corrección `PUT /api/transactions/{id}/category`.

### 3. Repositorios (`repository`)
- **`CategoryMappingRepository.java`**: Maneja el almacenamiento en memoria y búsqueda por patrón exacto (`findByDescriptionPattern`).
- **`CategoryKeywordRepository.java`**: Maneja las palabras clave en memoria y ejecuta la coincidencia (`matchDescription`).

### 4. Servicios (`service`)
- **`TextNormalizer.java`**: Limpia descripciones eliminando ruido (números, RUTs, fechas, acentos, múltiples espacios).
- **`CategoryClassifierService.java`**: Ejecuta la cadena de 4 niveles y la función `learnFromFeedback()`.
- **`MlInferenceService.java`**: Estructura (stub) lista para conectar con la API/endpoint del equipo de Ciencia de Datos mediante las propiedades `ml.inference.enabled` y `ml.inference.url`.
- **`TransactionService.java`**: Clasifica automáticamente en `create()` y procesa correcciones en `updateCategory()`.

### 5. Controlador (`controller`)
- **`TransactionController.java`**: Expone `POST /api/transactions` (crear con clasificación) y `PUT /api/transactions/{id}/category` (corrección y aprendizaje).

## 🗄️ Esquema de Base de Datos (`schema.sql`)

```sql
-- Tabla de mapeos colaborativos por retroalimentación
CREATE TABLE transaction_category_mappings (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    description_pattern VARCHAR(255) NOT NULL UNIQUE,
    category VARCHAR(50) NOT NULL,
    frequency INT DEFAULT 1
);

-- Tabla de palabras clave por categoría
CREATE TABLE category_keywords (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    keyword VARCHAR(100) NOT NULL UNIQUE,
    category VARCHAR(50) NOT NULL
);

CREATE INDEX idx_mappings_pattern ON transaction_category_mappings (description_pattern);
CREATE INDEX idx_keywords_category ON category_keywords (category);
```
